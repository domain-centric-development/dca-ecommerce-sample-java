# A new browser test cannot be titled after a scenario the spec does not hold yet — how does the build gate get green?

## Question

The build gate's `./gradlew test` fails on an existing test this story does not change:
`src/test/java/dev/domaincentric/sample/ecommerce/specification/SharedScenariosTest.java:97`
(`everyBrowserTestIsAScenarioOfThisShopsSpecification`) — "browser tests whose title is no scenario of
product/spec ==> expected: <[]> but was: <[Remove takes the line out]>".

The test (added in `7e3b7de`, the newest commit) requires every browser test's display name to be the title of
a scenario in `product/spec/**/scenarios.md`. The test gate requires the happy path's browser test
(`src/test-e2e/java/dev/domaincentric/sample/ecommerce/e2e/RemoveCartLineE2ETest.java:18`) to carry exactly that
title. But `product/spec/cart/shopping/scenarios.md` is written only by the gate that delivers the story — after
build. So any story that adds a browser test is red at build until delivery. Everything else is green: the six
criterion tests, the architecture suite, the formatter.

## Options

a) The story's stage writes its scenarios into `product/spec/cart/shopping/scenarios.md` before delivery (the
   delivering gate then finds them `holds`). Contradicts "written only by the gate that delivers".
b) `SharedScenariosTest` also accepts the titles of scenarios in stories under `product/epics/**/story.md` that are
   not delivered yet (a change to the test, in a commit of its own, outside this story).
c) The build gate (pipeline) leaves this test out until delivery, or the delivery gate runs it after the spec merge
   — a change in `dca-marketplace/plugins/dca-factory`.
d) The title goes into `TITLED_AFTER_THE_SHARED_SPECIFICATION` for now — its stale check then fails right after
   delivery, so this only moves the red.

## Recommendation

b) — the test's purpose (no browser test without a scenario) still holds, and every story in flight that adds a
browser test needs it, not only this one. Once it is in, this story's build runs again unchanged.

## Answer
answer: SharedScenariosTest also knows the titles of the stories not yet delivered (their `####` criteria, title = Title line else the key in words); the spec stays the only source for the Test-line and duplicate checks. Fixed on main in d5ce1e9; nothing changes in this story — run the stage again as it is.

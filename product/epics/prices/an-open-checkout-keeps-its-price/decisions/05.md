# The main line's test lines call two signatures this story changed. May the story's call replace them?

## Question

The runner's `main-tests` check sent the integrate step back for four test files. It wants the main line's lines put
back beside the story's, with nothing else edited. Each of those lines calls a signature the story changed, so put back
unchanged they would not compile:

- `CheckoutReferenceIntegrationTest.java` and `PaymentAtPlaceOrderIntegrationTest.java` lost
  `new ConfirmCheckoutCommand(checkout.sessionId(), checkout.customerId()));`. On this branch the record
  `ConfirmCheckoutCommand` has three components (`reviewFingerprint` added, plan `## Files`) and no two-argument
  constructor. The story's line is the same call with the fingerprint read from `GetCheckoutReviewInputPort` first.
- `ProviderPaymentIntegrationTest.java` lost `return submit("/checkout/confirm", page(REVIEW_STEP), "sentFrom", "review");`.
  It would compile, but Place Order then posts no `reviewFingerprint`, and the story refuses a confirmation that names
  no review. The story's line posts the same form plus the hidden fingerprint the review page renders.
- `CheckoutSessionAuthorizePaymentTest.java` lost four `session.authorizePayment("pay-1")` calls. On this branch
  `CheckoutSession#authorizePayment(String, Money)` takes the amount the provider authorized. The judge's ddd review
  asked for that change because the session recorded its stored total, not the reviewed one. The story's lines are the
  same calls with `Money.euro(15)`, the session's total, so every main-line case still asserts what it did. The story
  also adds one case with 14 EUR.

None of the main line's cases is dropped. All of them are still in each file with the same names and the same
assertions. Only the argument lists differ. The plan's `## Changed tests` names only `CheckoutSpecificationTest`, so
these four files are not recorded as changed by the story.

## Options

- a: Accept the story's lines as the resolution of these four files.
  Each one is the main line's call adapted to the signature the story changed. Record them as changed tests
  (the plan's `## Changed tests`, or wherever the runner's `main-tests` check reads exemptions from), and let the
  integrate gate run again.
- b: Put the main line's lines back literally and add compatibility overloads in production code.
  That means a two-argument `ConfirmCheckoutCommand` constructor and a one-argument `authorizePayment`. Both overloads
  would bypass the review check and the reviewed total this story introduces, and the integrate step may not edit
  production files.
- c: Send the story back to build to drop the signature changes.
  This reopens the judge's confirmed defect: the session would again record its stored total instead of the total the
  review showed.

## Recommendation

a — every main-line case and assertion is still there. Only the call shape changed, and the story's plan and judge
required that change. Putting the literal lines back cannot compile, and the overloads would undo what the story
delivers.

## Answer
answer: a — the story's lines are the resolution of the four files; from dca-factory 0.87.7 `main-tests` leaves out a test file an answered integrate decision names, and from 0.87.10 the integrate step applies this answer; nothing in the files changes, run the integrate step again.

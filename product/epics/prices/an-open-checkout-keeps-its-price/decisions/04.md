# The main line's payment spec names two browser tests that no longer exist — who corrects the two Test: lines?

## Question

The build gate is red on one case only, and the case is outside this story:
`SharedScenariosTest#everyBrowserTestAScenarioNamesExists`
(`src/test/java/dev/domaincentric/sample/ecommerce/specification/SharedScenariosTest.java:215`). Two `Test:` lines in
`product/spec/checkout/payment/scenarios.md` name browser tests that the story `the-payment-is-authorized-at-place-order`
removed from `ProviderPaymentE2ETest`:

- `authorized-payment-moves-to-review` (line 11) → `ProviderPaymentE2ETest#authorizedPaymentMovesTheCheckoutToReview`
- `the-payment-request-names-its-checkout` (line 115) → `ProviderPaymentE2ETest#thePaymentRequestCarriesTheCheckoutReference`

The spec file, `ProviderPaymentE2ETest` and `SharedScenariosTest` are the same on this branch as on `main`
(`git diff main` is empty for all three), so `main` is red on this case too. The gate itself says so: "outside this
story's change … the suite is red, not this story's code alone". The same story moved both scenarios to port tests:
`PaymentAtPlaceOrderIntegrationTest#choosingHowToPayRequestsNoPayment` and
`#placeOrderRequestsThePaymentWithTheCheckoutReference`. A stage may not write the spec (only the gate that delivers
writes it), and this story's file does not name these keys. Every other check of the build gate passes, and every
test of this story is green.

## Options

- a: Correct the two Test: lines on the main line, then let this story's build run again.
  Point them at `PaymentAtPlaceOrderIntegrationTest#choosingHowToPayRequestsNoPayment` and
  `PaymentAtPlaceOrderIntegrationTest#placeOrderRequestsThePaymentWithTheCheckoutReference`, the tests that replaced
  them. This happens in a commit of its own (`fix(checkout): …`), or by delivering
  `the-payment-is-authorized-at-place-order` again with its `## Moved tests`. Nothing in this story changes; after the
  main line is merged in, the build gate runs green.
- b: Add the two scenario keys to this story's `## Changed expectations`, so `SharedScenariosTest` passes them over while the story is open.
  This works today, but it ties a payment-spec defect to a price story, and the lines are still wrong after this story
  is delivered.
- c: Deliver this story with the main line's red case named as known.
  No file changes, but the build gate and the commit hook stay red until someone fixes the spec.

## Recommendation

a — the defect is the payment story's, it is red on `main` already, and the two replacement tests are known; fixing the
two lines where they live keeps this story's change to its own scenarios.

## Answer
answer: a — the two Test: lines are corrected on the main line (fa6873b8) to PaymentAtPlaceOrderIntegrationTest#choosingHowToPayRequestsNoPayment and #placeOrderRequestsThePaymentWithTheCheckoutReference; nothing in this story changes — merge the main line and run the build again. The cause, a Moved tests row naming the old test, is fixed in the pipeline (dca-factory 0.87.6).

# How does a new browser test pass `SharedScenariosTest` before delivery merges its scenario into `product/spec`?

## Question

The judge asked. The integrate gate refused the story on one unit test:
`SharedScenariosTest#everyBrowserTestIsAScenarioOfThisShopsSpecification` — "browser tests whose title is no
scenario of product/spec: [Each listener counts its own attempts]". The check came with `7e3b7de` on main, after
this story's test stage. The browser test's `@DisplayName` is exactly the scenario key in words
(`src/test-e2e/java/dev/domaincentric/sample/ecommerce/e2e/AttemptsPerListenerE2ETest.java:31`). But the scenario
reaches `product/spec/backoffice/eventlog/scenarios.md` only when the delivering gate merges the spec delta, and
that happens after integrate. So any story that adds a browser test is refused now. Neither the build stage nor
the test stage can fix this: the title is right, and the exception list only shrinks.

## Options

a. `SharedScenariosTest` also accepts the scenario keys of stories in flight (`product/epics/**/story.md`,
   `####` headings) as titles. This is a change to the project's own test, done by hand on main.
b. The pipeline merges the story's spec delta into `product/spec` before the integrate gate runs its suites.
   This is a change in `dca-factory`.
c. Leave the browser test untitled after the scenario until delivery. This is against `7e3b7de`'s intent, and the
   `@DisplayName` count check fails anyway.

## Evidence

- `.dca-factory/runs/each-listener-counts-its-own-attempts/.gate-integrate.txt` (suite `test` failed)
- `build/test-results/test/TEST-dev.domaincentric.sample.ecommerce.specification.SharedScenariosTest.xml:5`
- `src/test/java/dev/domaincentric/sample/ecommerce/specification/SharedScenariosTest.java:91-97`
- story `## Notes`: "the scenarios come into the spec with the tests that prove them"

## Recommendation

b. The spec is what holds once delivered, and the integrate suite checks the tree as it will be delivered. Until
the pipeline changes, a) is the smaller local fix. With either fix the story's tests stand as they are, and the
run resumes at the test stage.

## Answer
answer: SharedScenariosTest also knows the titles of the stories not yet delivered (their `####` criteria, title = Title line else the key in words); the spec stays the only source for the Test-line and duplicate checks. Fixed on main in d5ce1e9; nothing changes in this story — run the stage again as it is.

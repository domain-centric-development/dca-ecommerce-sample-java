# The story names refusal sentences the registration page no longer shows — which wording holds?

## Question

The story is `adopted`: it describes behaviour the shop already has. The refusals exist, but the sentences its
`Then` lines quote are the failures' log messages, not what the page shows:

| Key | Story's `Then` | What the page shows today |
| --- | --- | --- |
| taken-address-is-refused, taken-address-in-other-capitals-is-refused | "Email is already registered: anna.schmidt@example.com" | "This email address is already registered" (`src/main/java/dev/domaincentric/sample/ecommerce/account/adapter/incoming/web/RegisterPageController.java:171`) |
| second-registration-from-the-same-browser-is-refused | "User already has an account" | "You already have an account." (`src/main/java/dev/domaincentric/sample/ecommerce/account/adapter/incoming/web/RegisterPageController.java:172`) |

The story's sentences are the exception messages (`src/main/java/dev/domaincentric/sample/ecommerce/account/application/registeraccount/EmailAlreadyRegisteredException.java:20`,
`src/main/java/dev/domaincentric/sample/ecommerce/account/application/registeraccount/AccountAlreadyExistsException.java:20`).
The page showed them until commit `075958f` (WP-101, 2026-10-11, "word refusals from the failure's type and values,
never its message"); the replay story was written against the older page.

Everything else the story asks for holds today: the address is normalised before the check
(`src/main/java/dev/domaincentric/sample/ecommerce/account/domain/model/Email.java:31`), the use case refuses a
taken address and a second account for the same user
(`src/main/java/dev/domaincentric/sample/ecommerce/account/application/registeraccount/RegisterAccountUseCase.java:58-67`).
No existing test covers either refusal on the page.

An adopted story cannot have a scenario the code does not show, and the adopt gate cannot get a characterization
test green against these sentences without changing production code.

## Options

1. **Change the story to today's page sentences** — "This email address is already registered" (both address
   scenarios) and "You already have an account." Stays adopted; characterization tests, no code change. Keeps the
   WP-101 rule that a page never shows a failure's message.
2. **Keep the story's sentences and make it a delivered story** (`status` back to a buildable state) — the page goes
   back to showing them, which reverses WP-101 for the register page and has to be mirrored in the .NET sample.
3. **Option 1, and also name the address in the page's sentence** (e.g. "This email address is already registered:
   anna.schmidt@example.com") — then a code change, so not adoptable either; it becomes a delivered story.

## Recommendation

Option 1. The difference is the old log-message wording, not behaviour anyone chose for the page. WP-101 replaced it
on purpose, and the story's intent, one account per address and per browser, holds as it stands.

## Answer
answer: 1 — the story carries today's page sentences: "This email address is already registered" (both address scenarios) and "You already have an account.". It stays adopted; the story text is already changed, in both shops alike.

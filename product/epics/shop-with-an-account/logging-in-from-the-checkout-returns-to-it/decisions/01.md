# The happy-path test's title is too long for the test gate to find it in the report

## Question

The scenario's `Title:` ("A guest who logs in from the buyer step returns to the checkout after the cart take-over,
with the order", 105 characters) must be the e2e test's `@DisplayName` verbatim (`test-titles`). google-java-format
(`spotlessApply`, profile `formatFix:`) cannot fit `@DisplayName("…")` within 100 columns and always wraps it as
`@DisplayName(` / `"…")` on two lines. The JUnit XML report names the case by its display name only, and the gate's
`tests-red` check reads the display name one source line at a time (`@DisplayName\s*\(\s*"` must be on one line), so
it reports "no test report from this run shows it ran" although the test ran and failed (`1 test completed, 1 failed`).
Which way should it go?

## Options
- a: Shorten the scenario's `Title:` in the story to 86 characters or fewer, e.g. "A guest who logs in from the buyer step
  returns to the checkout with the order" — the test then carries it on one line.
- b: Teach the gate (dca-factory, `reports.py` `display_name_of`) to read an annotation whose string sits on the next
  line, and update the installed pipeline; the story stays as it is.
- c: Set `testEvidence: exit-code` in `dca-factory.profile.yaml` — the weaker red proof the gate offers, for every story.

## Evidence
- `src/test-e2e/java/dev/domaincentric/sample/ecommerce/e2e/LoginFromTheCheckoutE2ETest.java:25` — the wrapped annotation
  after `spotlessApply`
- test gate run: `test-titles` passed, `tests-red` refused with the message above

## Recommendation
b — the defect is in the gate's reader and will meet every long title; a is the quick way to let this story go on
without touching the pipeline.

## Answer

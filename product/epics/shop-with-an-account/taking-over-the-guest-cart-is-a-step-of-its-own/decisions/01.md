# A new browser test is red in SharedScenariosTest until the story is delivered — how does a story in flight pass?

## Question

`src/test/java/dev/domaincentric/sample/ecommerce/specification/SharedScenariosTest.java:97`
(`everyBrowserTestIsAScenarioOfThisShopsSpecification`, added in commit 7e3b7de) requires every browser test's
display name to be the title of a scenario in `product/spec/**/scenarios.md`. This story's happy path is a browser
test titled "Continue takes the guest cart over" (`CartTakeOverWithoutScriptE2ETest`). Its scenario reaches
`product/spec/cart/cartrecovery/scenarios.md` only when the gate that delivers merges it. So the required `test`
suite is red at the build gate, and it will be for every story that adds a browser test. The production code is
done: every mapped test and the architecture suite are green, and the formatter is clean.

## Options

- **a — the check also knows the stories in flight.** `SharedScenariosTest` also accepts the scenario titles of
  approved stories under `product/epics/**/story.md` that are not yet delivered. Changed by hand as a fix outside
  this story; the build runs again unchanged.
- **b — this story writes its scenarios into `product/spec` ahead of delivery.** This goes against the rule that
  only the delivering gate writes the spec, and the spec-delta check may then see "holds" rather than "adds".
- **c — exempt the title for now.** Add "Continue takes the guest cart over" to
  `TITLED_AFTER_THE_SHARED_SPECIFICATION`. The list's stale check fails as soon as delivery makes the title a
  scenario, so delivery would also have to remove it.

## Recommendation

a — the conflict is between the new check and the pipeline's order, not in this story; fixing it at the check
keeps every later story with a browser test from stopping here.

## Answer
answer: SharedScenariosTest also knows the titles of the stories not yet delivered (their `####` criteria, title = Title line else the key in words); the spec stays the only source for the Test-line and duplicate checks. Fixed on main in d5ce1e9; nothing changes in this story — run the stage again as it is.

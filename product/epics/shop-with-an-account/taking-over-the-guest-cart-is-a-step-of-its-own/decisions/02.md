# The build gate counts main's fix to SharedScenariosTest as this story's change — how does the build pass?

## Question

The build gate refuses with two checks that are not about this story's code:

- `tests-kept`: `src/test/java/dev/domaincentric/sample/ecommerce/specification/SharedScenariosTest.java` "existed
  before this story and no longer expects what it did". It changed in d5ce1e9 on main (the answer to decision 01).
  The runner brought d5ce1e9 into this branch at 20:41 local time (the file's mtime). The story's `.tests-baseline`
  in the evidence folder is from 18:21 and still holds the old digest (line 71).
- `files-listed`: `.vscode/launch.json` and `.vscode/settings.json` count as changed. `git diff` against the
  story's `base-tree` (729bf61) shows no change to either file, and `git status` is clean for them. Neither
  appears in `changed.txt` or `tree-before-builder.txt`.

`git diff 729bf61` lists only the nine files the story changed (plus the linked folders). This stage changed no
file in this round.

## Options

- a: The pipeline records the tests baseline again after it brings main into a story's branch, and works out
  "changed" from the base tree. Fixed by hand in the pipeline, outside this story. The build runs again unchanged.
- b: The plan's `## Changed tests` lists `SharedScenariosTest`, backed by decision 01, and build.md lists the two
  `.vscode` files as unchanged by this story. This fixes the story's files rather than the cause, so the next
  story that takes in main hits the same refusal.

## Recommendation

a: the baseline went stale when main was brought in, which is the runner's doing. Fixing it there keeps every
story that takes in a fix from main from stopping here.

# May StockLevelRefusalTest follow the rename of decreaseStock to sell?

## Question
Finding row 1 asks for one `StockLevel` operation for a sale that consumes its reservation and raises its own event.
The build made `decreaseStock(amount)` that operation and renamed it `sell(amount)`; it raises `StockSold`, which replaces
`StockDecreased`. Only the sale called `decreaseStock`, so keeping it beside `sell` would leave code without a caller.
`src/test/java/dev/domaincentric/sample/ecommerce/inventory/domain/model/StockLevelRefusalTest.java` calls the old name
at `:26` (`decreaseStock(5)` refused with `InsufficientStock`, naming 4 held) and `:64` (`decreaseStock(-1)` stays an
argument guard). Both lines now call `sell` and assert exactly what they asserted before. The gate (`tests-kept`) treats
this as a change to an existing test and wants a human to back it.

## Options
- a: Yes, the test follows the rename, and the build goes on as it stands.
  The two calls become `sell`; every assertion stays as it was. The plan's `## Changed tests` row cites this record.
- b: No, keep `decreaseStock`, give it the sale's meaning, and leave the test untouched.
  No rename. The name keeps saying "decrease" for an operation that also consumes a reservation, and the glossary entry for it is reworded.
- c: No, keep `decreaseStock` as it was beside the new `sell`.
  The test stays as it is. `decreaseStock` keeps no caller outside its test, which is the dead-code kind of finding this task exists to close.

## Recommendation
a — the test's expectations do not change, only the name it calls; `sell`/`StockSold` uses the glossary's own words ("stock has been sold", "a sale consumes the reservation").

# May the unit test that holds the review fingerprint's null refusal change to the missing fingerprint matching no review?

## Question
The story moves the answer to a missing fingerprint from the page into `ReviewFingerprint`, and says "The unit test of
the review fingerprint names the missing one." One test that existed before contradicts that:

- `src/test/java/dev/domaincentric/sample/ecommerce/checkout/domain/model/ReviewFingerprintTest.java:17-21`
  (`refusesAMissingValue`). Today it expects `ReviewFingerprint.of(null)` to throw `IllegalArgumentException`. After
  the story it would expect `ReviewFingerprint.of(null)` to be unequal to a review's fingerprint and to name no
  changed line (`aMissingValueMatchesNoReviewAndNamesNoLine`).

The story has no `## Changed expectations` section, so nothing a person wrote backs the change in the form the gate
reads (`tests-kept`). The page's answer does not change: a form without a fingerprint still places nothing and leads
back to the review.

## Options
- a: The test changes as described; the plan cites this record in its `## Changed tests` row.
  The value object reads a missing fingerprint itself, as WP-170 decision 2 asks; the build is already written that way.
- b: The old test stays; a second factory reads the sent value, and `of` keeps refusing null.
  `ReviewFingerprint.of(String)` stays the code-side contract, and a new `sent(@Nullable String)` maps a missing value
  to a fingerprint of no review. That needs a stand-in value inside the record, so absence becomes a value again,
  just inside the model, and the value type gets two ways in.
- c: Supersede the story and keep today's adapter default.

## Recommendation
a — the story already asks for the unit test to name the missing one, and a nullable value that matches nothing is the smallest change that puts the answer in the model.

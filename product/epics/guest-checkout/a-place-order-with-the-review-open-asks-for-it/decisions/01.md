# A new browser test cannot pass SharedScenariosTest before the delivering gate writes its scenario into product/spec

## Question

`src/test/java/dev/domaincentric/sample/ecommerce/specification/SharedScenariosTest.java:97`
(`everyBrowserTestIsAScenarioOfThisShopsSpecification`, added in 7e3b7de) requires every browser test's
`@DisplayName` to be the title of a scenario in `product/spec/**/scenarios.md`. That spec is written only by the
gate that delivers a story. So the happy-path e2e test this story's test stage wrote
(`StepsShowTheProgressE2ETest#aPlaceOrderSentFromThePaymentStepWithTheReviewOpenLeadsToTheReview`, titled
"Place order with the review open asks for the review", the key in words as the test gate requires) fails the
required `test` suite at the build gate. The build itself is green: the e2e test, the architecture suite and the
formatter pass. The same refusal will meet every story that adds a browser test. Which side gives way?

## Options

- **a** — `SharedScenariosTest` also accepts the title of a scenario in a story under `product/epics/` that is
  not delivered yet (status approved/running). A delivered story's scenarios are in `product/spec` anyway.
  The test changes once, in the project, and is not tied to this story.
- **b** — this story adds its title to `TITLED_AFTER_THE_SHARED_SPECIFICATION`, and a follow-up takes it off once
  the spec holds it. The list's own stale check then fails right after delivery, so every story needs two edits.
- **c** — the stage writes the scenario into `product/spec/checkout/steps/scenarios.md` before delivery. This
  breaks "the spec is written only by the gate that delivers".
- **d** — `SharedScenariosTest` leaves the required suites and runs only at delivery or in CI.

## Recommendation

**a**. Its intent (no browser test without a scenario) still holds: a story's scenario is a scenario, and the
gate moves it to the spec at delivery. The change belongs to whoever owns 7e3b7de, outside this story. After it
lands, this story's build reruns unchanged.

## Answer
answer: SharedScenariosTest also knows the titles of the stories not yet delivered (their `####` criteria, title = Title line else the key in words); the spec stays the only source for the Test-line and duplicate checks. Fixed on main in d5ce1e9; nothing changes in this story — run the stage again as it is.

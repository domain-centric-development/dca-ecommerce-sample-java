# The main line's payment spec names a test that was never committed, and every story's gate refuses on it

## Question

The judge passed this story, and its documents match the code. The document gate (and the integrate gate before
it) still refuses with `spec-tests`: `product/spec/checkout/payment/scenarios.md:85,93,101` name
`dev.domaincentric.sample.ecommerce.checkout.CheckoutReferenceIntegrationTest` (`twoCheckoutsSendTwoDifferentReferences`,
`theProvidersAnswerForOneCheckoutTouchesNoOther`, `aSecondAttemptCarriesTheSameReference`). That class is in no
commit (`git log --all` on its path is empty). The story each-payment-names-its-checkout delivered those scenarios
(50bf3b4), but its code commit 318da30 does not carry the test. This story did not touch the file. Its document
stage may change no code and no spec, so it cannot clear the refusal. Who repairs the main line?

## Options

- a: Repair the main line by hand: commit the missing `CheckoutReferenceIntegrationTest` from the
  each-payment-names-its-checkout worktree if it is still there, or else correct those three `Test:` lines to the
  test that proves the scenarios. Then run this story's document stage again as it is.
- b: Reopen each-payment-names-its-checkout as a story or a task that writes the missing integration test. This
  story waits until it is delivered.
- c: Deliver this story while the gate refuses. This breaks "every gate passed" for a cause outside the story.

## Recommendation

a: the defect is one file the other story forgot, so a repair by hand on main is the shortest path. Nothing in
this story changes; it reruns unchanged afterwards. Also worth checking why the delivering gate of
each-payment-names-its-checkout let a missing test through.

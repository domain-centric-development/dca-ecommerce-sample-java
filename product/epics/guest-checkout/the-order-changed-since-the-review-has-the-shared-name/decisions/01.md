# May the four tests that name the failure inside `assertThrows` follow its new name?

## Question
The story renames `CheckoutChangedSinceReviewException` to `OrderChangedSinceReviewException` and says "a test that existed
before it stays as it is". Four tests name the type as the argument of `assertThrows`, so the rename changes the line
that carries their assertion — the gate's `tests-kept` check reads that as an expectation that no longer holds, and
the story has no `## Changed expectations` to back it. What each test asserts — the refusal, the product named or
not, nothing changed on the session — stays word for word; only the type's name follows.

Evidence read:
- `src/test/java/dev/domaincentric/sample/ecommerce/checkout/domain/model/CheckoutReviewTest.java:108`, `:146`
- `src/test/java/dev/domaincentric/sample/ecommerce/checkout/domain/model/CheckoutSessionReviewTest.java:95`
- `src/test/java/dev/domaincentric/sample/ecommerce/specification/CheckoutSpecificationTest.java:108`
- `src/test-integration/java/dev/domaincentric/sample/ecommerce/checkout/OrderAtTodaysPriceAfterReopeningTheReviewIntegrationTest.java:109`, `:156`
- the story: "It stays one type" — so no alias of the old name may remain
- `src/test-integration/java/dev/domaincentric/sample/ecommerce/checkout/OrderChangedSinceTheReviewIntegrationTest.java:106` names the type in a `throw`, not in an assertion, and passed the check

## Options
- a: The four tests follow the type's name inside `assertThrows`; what each asserts stays as it is (changes a test's
  line, not its claim). The plan lists them under `## Changed tests` citing this record.
- b: Keep `CheckoutChangedSinceReviewException` as a deprecated subclass of the new type so the four tests stay
  byte for byte. Contradicts the story's "it stays one type" and leaves the old word in the code.
- c: Change the story so it names the tests that follow the name under a `## Changed expectations` section, and
  plan again.

## Recommendation
a — the rename is the story's whole content, and a test that names a type can follow its name without asserting
anything new; the `tests-kept` check cannot tell a renamed type from a changed expectation, which is a finding for
the pipeline, not for this story.

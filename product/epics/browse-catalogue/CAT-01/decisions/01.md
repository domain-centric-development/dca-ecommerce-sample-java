# The e2e suite reaches a foreign service on localhost:8080, not the shop

## Question
The test gate refused CAT-01 because
`SeededCatalogE2ETest#catalogListsTheSeededProductsInNameOrder` (criterion
`catalogue-lists-the-seeded-range`, level e2e in `tasks/CAT-01/plan.md:44-46`) timed out waiting for
`[data-test='product-card']` (`tasks/CAT-01/.gate-test.txt:16`). The test is unchanged and correct. The
cause is the environment:

- `./gradlew test-e2e` does not start the shop. It drives whatever serves `e2e.baseUrl`, and that
  defaults to `http://localhost:8080` (`gradle/plugins/test-e2e.gradle`, "requires running
  application"). The profile runs `e2eTest: ./gradlew test-e2e --rerun` and starts nothing
  (`.agents/factory/factory.profile.yaml:7`).
- A throwaway probe (since deleted) opened `http://localhost:8080/products` in the same suite. It got
  HTTP 404 with the JSON body `{"code":"BAD_REQUEST","message":"Bad Request"}`. That is another
  service holding port 8080. This shop renders an HTML catalogue there.

To start the application for the e2e run, or to point the suite at another port, the build, the
runner configuration or the stack profile has to change. The test stage may change none of these.
Freeing the port on this machine is outside the repository.

## Options
- a: Stop the service on port 8080 and run the shop there (`./gradlew bootRun` or
  `docker compose up --build`) whenever the gate runs `test-e2e`. Nothing in the repository
  changes, but every e2e gate depends on a manually started shop.
- b: Make the profile's `e2eTest` start the shop on a free port and pass it as `-De2e.baseUrl=…`
  (for example a wrapper script, or a Gradle task that boots the app before `test-e2e`). This is
  a stack decision and makes the e2e gate self-contained.
- c: Keep the environment as it is and accept the criterion as `uncovered` for this story. It stays
  covered only by the existing test, which is not run.

## Recommendation
b. The e2e gate should not depend on what happens to be listening on port 8080. Until b is in
place, a unblocks CAT-01 without touching the repository.

## Answer
answer: The end-user suite now starts the shop itself, in the test process and on a free port — nothing has to run beforehand. Run the test stage again; the end-user tests run as they are.

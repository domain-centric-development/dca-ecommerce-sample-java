# The spec still names three browser tests this story moved or removed — how does the suite go green before delivery?

## Question
The build gate's required suite is red on one test outside the story:
`src/test/java/dev/domaincentric/sample/ecommerce/specification/SharedScenariosTest.java:183`
(`everyBrowserTestAScenarioNamesExists`) asserts that every `Test:` line in `product/spec/**/scenarios.md` names a
browser test some e2e source holds. `product/spec/checkout/payment/scenarios.md` still names
`ProviderPaymentE2ETest#authorizedPaymentMovesTheCheckoutToReview` (line 11),
`#thePaymentRequestCarriesTheCheckoutReference` (line 79) and `#payingAgainForTheSameAmountKeepsThePayment`
(line 111). The plan moved the first two to integration tests and removed the third (story `## Changed
expectations`, lines 1, 3 and 4; tests.md `## Moved tests`). The spec is written only by the gate that delivers
the story, so before delivery the old `Test:` lines stay, and no production code can make the test green. The
story's own tests are all green.

## Options
- a: Let the build gate count a spec `Test:` line that the story's `## Moved tests` or the plan's removed scenarios
  name as already replaced, so the suite runs green before delivery.
  A pipeline change (gate or `SharedScenariosTest`); the story waits for it.
- b: Let this story rewrite the three `Test:` lines in `product/spec/checkout/payment/scenarios.md` in its branch now.
  An exception to "the spec is written only by the delivering gate", for this story.
- c: Keep the three e2e methods in `ProviderPaymentE2ETest` under their old names until delivery, asserting the
  new behaviour. Two browser tests where one is needed, and names that say the old behaviour, to be removed by hand later.

## Recommendation
a — the same gap meets every story that moves or removes a browser test the spec names; closing it in the gate
keeps the spec single-writer and needs no workaround in the tests.

## Answer
answer: a, in `SharedScenariosTest`, not in the gate: a `Test:` line need not name an existing browser test while a story that is not delivered yet changes or removes that scenario — the exemption the test already grants undelivered stories for titles; the plan lists the test under `## Changed tests`. Same answer as the .NET shop's decision the-payment-is-authorized-at-place-order-01.

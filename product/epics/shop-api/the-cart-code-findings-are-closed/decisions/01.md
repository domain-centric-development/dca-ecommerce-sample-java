# May this task change the two existing tests its stock findings name?

## Question
Two of the rows this task closes name an existing test as their fix. `the-cart-holds-no-more-than-is-in-stock#2`
removes the one-number `CartPageNotice.redirectTo(path, count, attributes)`, which has no production caller left;
`src/test/java/dev/domaincentric/sample/ecommerce/cart/adapter/incoming/web/CartPageNoticeTest.java:86` calls it, so
the test has to call the varargs form instead (a one-number notice, `ITEMS_UNAVAILABLE`, 3). `#3` asks for distinct
numbers in the same test (`:46`, `1, 8, 8` → `1, 5, 8`, with the expected sentence following) and for two more
assertions in `src/test-integration/java/dev/domaincentric/sample/ecommerce/cart/AddItemToCartIntegrationTest.java:75`
(`held()` 5, `inStock()` 8). What each test asserts stays: the redirect, the flash attributes, the sentence. The
story is a task with no `## Changed expectations`, so the build gate refuses the changed test without a person's
answer. The changes are in the worktree; the build gate is otherwise unrun.

## Options
- a: Yes — the task changes both tests as the findings' fixes say.
  The build gate then passes `tests-kept`; the plan's `## Changed tests` rows cite this record.
- b: No — keep the overload and the test as they are.
  The task drops `the-cart-holds-no-more-than-is-in-stock#2` and `#3` from `closes:`, and they stay open for a story of their own.

## Recommendation
a — the findings' own fix names these tests, nothing an actor sees changes, and every assertion stays: the overload
is dead code and the identical numbers hide a swap of "held" and "in stock".

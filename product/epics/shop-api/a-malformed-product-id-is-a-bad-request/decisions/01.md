# SharedScenariosTest refuses a new browser test until the delivering gate writes its scenario into product/spec — how does a story's build pass it?

## Question
The build gate runs `./gradlew test` whole and it fails on one test only:
`src/test/java/dev/domaincentric/sample/ecommerce/specification/SharedScenariosTest.java:97`
(`everyBrowserTestIsAScenarioOfThisShopsSpecification`) — "browser tests whose title is no scenario of product/spec ==>
expected: <[]> but was: <[A malformed product id is a bad request]>".

The story's happy-path test `ShoppingCartApiE2ETest#addingAProductIdThatIsNoUuidIsABadRequestAndLeavesTheCartEmpty`
carries its scenario's title, as the test gate requires (`test-titles`). But `product/spec/**/scenarios.md` gains the
scenario only when the gate that delivers merges the story — after build, tidy, judge and document. The test came in
with commit 7e3b7de, the newest on the line; every story that adds a browser test will hit the same wall. Its escape
list `TITLED_AFTER_THE_SHARED_SPECIFICATION` (line 42) "only shrinks" and fails as stale once the title is a scenario,
so the build cannot use it either. The build may not change an existing test (`tests-kept`), and may not write
`product/spec` (only the delivering gate does). Everything else is green: the story's two tests, the architecture
suite and the formatter passed the same gate run.

## Options
- a: Widen `SharedScenariosTest` to also accept the titles of scenarios in stories under `product/epics/**/story.md`
  that are not delivered yet (approved, running) — the test then guards drift, not timing (changes a test; a fix by
  hand outside this story, then the build gate runs again).
- b: The pipeline merges the story's spec delta into a scratch `product/spec` before it runs the required suites at the
  build and tidy gates (a change to the pipeline in dca-marketplace; nothing in this repository).
- c: Take `SharedScenariosTest` out of the `test` command's required run and keep it for the delivering gate only
  (changes the build configuration or the profile).

## Recommendation
a — it is the smallest fix, lives in this repository, and keeps what the test is for (no browser test titled after
nothing) while letting a story in flight carry the title its scenario will have. The story's code stays as it is.

## Answer
answer: SharedScenariosTest also knows the titles of the stories not yet delivered (their `####` criteria, title = Title line else the key in words); the spec stays the only source for the Test-line and duplicate checks. Fixed on main in d5ce1e9; nothing changes in this story — run the stage again as it is.

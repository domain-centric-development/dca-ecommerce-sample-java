# How does a new end-to-end scenario test pass SharedScenariosTest before its scenario is in product/spec?

## Question
The judge asked. The integrate gate's `./gradlew test` fails on
`SharedScenariosTest#everyBrowserTestIsAScenarioOfThisShopsSpecification`
(`src/test/java/dev/domaincentric/sample/ecommerce/specification/SharedScenariosTest.java:97`): unknown title
"No active cart is not found". That title is the story's own key in words, and the test
(`src/test-e2e/java/dev/domaincentric/sample/ecommerce/e2e/ShoppingCartApiE2ETest.java:96`) is titled correctly.
The scenario is missing only because `product/spec/cart/shopping/scenarios.md` is written by the gate that
delivers, after integrate (gate `spec-delta`: "2 added … nothing that holds changes"). The check came to main in
7e3b7de, after this story was planned and judged. No stage of the story can fix this legitimately: adding the
title to `TITLED_AFTER_THE_SHARED_SPECIFICATION` (line 42) fails as "stale" as soon as delivery merges the
scenario. So every story that adds an e2e test for a new scenario now fails at integrate.

## Options
- a: The pipeline merges the story's spec delta into `product/spec` before the integrate suite runs (fix in the
  dca-factory gate/runner, not in this story); the story then integrates unchanged.
- b: The plan moves `no-active-cart-is-not-found` to integration level, like its neighbours
  (`opening-a-cart-for-the-caller`, `the-callers-active-cart-by-customer-id`): its test moves into
  `ShoppingCartApiIntegrationTest`, and the e2e test is dropped (changes a test).
- c: `SharedScenariosTest` also accepts the scenario titles of the stories that are running (`product/epics`), so the
  check holds both before and after delivery (changes a test outside this story).

## Recommendation
a: the gap is in the order of the pipeline, not in this story, and every later story with a new e2e scenario
hits it too. b unblocks this one story now, at the cost of the e2e level that the plan chose for the happy path.

## Answer
answer: SharedScenariosTest also knows the titles of the stories not yet delivered (their `####` criteria, title = Title line else the key in words); the spec stays the only source for the Test-line and duplicate checks. Fixed on main in d5ce1e9; nothing changes in this story — run the stage again as it is.

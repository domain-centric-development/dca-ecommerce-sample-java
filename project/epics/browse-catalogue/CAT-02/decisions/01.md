# BaseE2ETest changed after CAT-02's baseline was recorded, by the fix for CAT-01-01

## Question
The test gate refused CAT-02 on `tests-kept` (`tasks/CAT-02/.gate-test.txt:20`). It says
`src/test-e2e/java/dev/domaincentric/sample/ecommerce/e2e/BaseE2ETest.java` no longer expects what it
did, and the plan has no `## Changed tests` section that lists it.

This story did not change that file. The plan gate recorded the baseline at 2026-09-26 00:35 local
(`tasks/CAT-02/.tests-baseline:61`, blob `a447d6c`). Then commit `33236c6` (2026-09-26 08:01 +0200,
"the browser suite starts the shop itself") carried out the answer to CAT-01-01. It replaced

    protected static final String BASE_URL =
        System.getProperty("e2e.baseUrl", "http://localhost:8080");

with `protected static final String BASE_URL = ShopUnderTest.baseUrl();` and reworded two lines of
the class comment. The working tree has no uncommitted change to the file.

The test stage has no way to satisfy the gate on its own:
- Restoring the old lines would revert a committed change that the whole browser suite, including
  `ProductPageE2ETest`, depends on.
- `## Changed tests` belongs to the plan, which the test stage does not write.
- The story has no `## Changed expectations`, and the gate accepts only an answered decision.

## Options
- a: Accept the change for this story. An answered decision with `stage: test` for CAT-02 is enough
  for `tests-kept` to pass, and nothing in the repository changes.
- b: Re-run the plan stage for CAT-02 so that the plan lists `BaseE2ETest.java` under
  `## Changed tests`, with its row citing this decision as the backing.
- c: Record a new baseline for CAT-02 that includes commit `33236c6`: delete
  `tasks/CAT-02/.tests-baseline` and pass the plan gate again. The file is written only once per story
  (`record_tests_baseline`), so a human has to do this.

## Recommendation
a. The change came from a human decision (CAT-01-01) that was already applied, not from this story.
Answering it keeps the audit trail and needs no re-plan and no hand-edited gate file.

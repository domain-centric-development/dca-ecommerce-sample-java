## Considered and dropped
- The integration tests read the rendered HTML as text: the rule "an end-user test reads markup
  instead of driving the browser" does not apply. These are integration tests at the level the plan
  set for every scenario except the happy path. That level is the one the test-level rule asks for,
  and the happy path runs in Playwright (`HomePageE2ETest`).
- `HomePage.heroText` reads `textContent` rather than `innerText`: the scenario asserts the
  subtitle's words, not the capitals CSS gives them. The comment at `HomePage.java:102` describes
  the present state, not history.
- `shop-now-opens-the-catalogue`: the test checks that the link is in the same `cta-section` as the
  heading and the sentence, not that it sits below them. Inside that section the link comes after
  both (`index.pug:62-65`), and treating the section as the unit is a fair reading of "below". Minor
  at most, not recorded as blocking.
- The Shop Now break (`href="/"`) fails because the home page's `h1` holds a `span`, not because
  the heading text differs. That is an incidental reason, but the test still rejects the wrong
  target, and a target with a plain `h1` other than "Our Products" would fail on `isEqualTo`.
- Break patches not checked one at a time with `git apply` (`tests.md`, Notes): a gate and
  test-stage concern. The patches are in `tasks/CAT-04/breaks/`, and the combined run failed 7 of 7
  on each test's own assertion.

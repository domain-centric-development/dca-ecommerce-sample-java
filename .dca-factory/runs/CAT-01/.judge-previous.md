## Considered and dropped
- The `Given` of `catalogue-lists-the-seeded-range` names `seed-catalogue.json`, and this repository has
  no such file. The seed is created in code, by `SampleDataInitializer.loadSampleProducts()`. The plan
  already records this under `## Open assumptions`. Its reading is that the file stands for the shared
  sample catalogue (the story's note gives `scenario.catalog.seeded-in-name-order`). That reading is
  supported by `SeededCatalogE2ETest.java:10-12`, which calls this the same 21-product seed as the .NET
  sample. The behaviour the scenario asserts (21 cards from the start-up seed) is proved, so this is not
  a defect in the tests. If the story really means that this sample must load that file, the story
  should be corrected in the backlog. The code does not need to change.
- `SeededCatalogE2ETest.java:22` counts the card titles, not the cards. `catalog.pug:14,21` renders
  exactly one `product-card-title` in each `product-card`, so the count of titles equals the count of
  cards. Not a defect.
- `ProductCatalogPageIntegrationTest.java:42` (`HEADING`) takes the first `<h1>` in the page. If the
  layout ever gains an `<h1>` before this one, the test fails; it cannot falsely pass. Not a defect.
- `ProductCatalogPageIntegrationTest.java:99` checks the target page only by `contains(title)`. The same
  test also asserts, on line 90, that each target is `/products/<uuid>` and, on line 95, that the target
  answers 200. The scenario asks for "a link to that product's page". What that page shows belongs to
  `CAT-02`. This is enough for this criterion. Not a defect.
- `cardShowsTheProductsNameDescriptionAndImage` checks the image by its `src` only, not its `alt`. The
  scenario asks for "its image", and the `src` is the seeded image URL (`/images/products/ddd-book.webp`).
  The plan states this reading. Not a defect.
- The diff also contains `ProductPageE2ETest`, `ProductDetailPageIntegrationTest`, and the page-object
  additions `viewProductNamed` and `heading`. These belong to `CAT-02`, not to this story, and no
  CAT-01 criterion maps to them. They were not reviewed here.
- The diff also contains `ShopUnderTest` and the edits to `BaseE2ETest`, `BasePage`, `test-e2e.gradle`
  and `README.md`. Together they make the e2e suite start the shop itself. They apply the answered
  decision `CAT-01-01`, and the gate accepted them as changed on that decision. In adopt mode only the
  proof of each scenario is reviewed, so they were not reviewed further.
- Breaks: each patch changes exactly what its test depends on. The order break reverses `BY_NAME`. The
  description break drops the `p.product-card__description` text. The link break changes the label
  "View Details" to "View". The heading break changes `h1 Our Products` to `h1 Products`. None changes
  something its test does not depend on. `tests.md` notes that the patches were written by hand and
  never checked with `git apply --check`. They record the break and do not affect the verdict.
